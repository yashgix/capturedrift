Claude Code · Codex · session traces

capturedrift

Measures silent data loss when coding-agent session logs from many Claude Code and Codex versions are captured into a standard trace schema, measured on real public sessions.

The problem

A capture tool can store raw sessions first and normalize them later, so the raw log is safe. The importer in front of it is not. It encodes one CLI version's field layout. Later versions keep the old fields and add new ones, so the importer keeps running and keeps succeeding. It just never reads the new shapes. No exception, no warning, no log line.

capturedrift puts a number on that gap, on 40 real session files from public Hugging Face datasets that span 22 Claude Code versions and 4 Codex versions. It models a generic importer. It makes no claim about any particular product's code.

Result

The share of text that is lost, shown as a range because it depends on how copies are counted. The low end is text with no exact or approximate counterpart in what the parser kept (not matched). The high end adds text that is an approximate copy, which is a heuristic and could hide a missing long line. Held-out means sessions from versions after the cutoff.

How it works

Everything is a key: a record kind plus a path into the record, such as assistant and message.content[]<text>.text. Sizes are compact JSON bytes, so the accounting adds up exactly. Two parsers are modelled and measured on the same ruler.

  • Frozen parser. Knows only the keys in the sessions up to a cutoff version. Everything later is held out. The split is by version, not by date, because a parser is frozen at a version and session dates are not in version order.
  • Fixed common schema. A normalizer into Hugging Face's Session Traces Simple Format, reading a fixed table of paths per harness. The share it reads is measured, and what normalize actually writes is checked against it.
  • Alarms. Three simple checks that see only the first session of a new version: a new record kind, any new key, or new keys above a byte threshold chosen on training versions only.

Limits

  • Small data. 40 sessions, at most two per version. Codex has five sessions and three held-out versions.
  • Codex training is one version (0.125.0), so it has no training-period version change. The byte threshold is tuned on Claude Code only.
  • Version and source are confounded. Different versions mostly come from different people and setups.
  • Copies are matched on text. The approximate copy rule is a heuristic, which is why loss is a range.
  • The mapping was chosen late. It was written after looking at all versions, so its share is a best case for a fixed mapping.
  • Redaction. The sessions are public and were redacted for credentials, emails, home paths, third-party cookies and URL signatures. The redaction is pattern-based, so it is best effort.
  • No session in this data contains subagent records, so that case is tested only on synthetic records.

Do simple alarms catch it?

Not well. A case is a record kind with new keys in a held-out version. Alarms fire often on new keys that carry no text, so precision is low, and with this few cases the 95% Wilson intervals are wide. Treat the alarms as a noisy hint, not a detector you can rely on. For example, the any-new-key alarm on Claude Code fired 24 times and 20 were false alarms (precision 0.17), and on Codex it fired 28 times with 15 false alarms (precision 0.46). The labels also come from version changes. A case counts as real when a new key carries text, not because a real importer was seen to break, so this measures a proxy for drift and not observed drift.

What version 2 changed and why

The first version had two weaknesses. Version 2 fixes both without changing any v1 number.

  • The common-schema share counted bytes at mapped key paths, so a normalizer bug (it read thinking text from the wrong field) did not move it. Version 2 counts what normalize writes and fails a test if that drifts from what the mapping reads.
  • "Unseen" text included copies of kept content. Version 2 splits it into exact copy, approximate copy and not matched, and reports loss as a range.
  • It also adds per-kind alarm counts with intervals, keys that went quiet, kinds new to a harness, and tests that pin how sidechain and compacted records are handled.

Data and licenses

The 40 session files come from 12 public, ungated Hugging Face datasets at fixed commits, under MIT, Apache-2.0, CC0-1.0 or CC-BY-4.0. Home-directory user names, email addresses, credential-shaped strings, third-party cookie values and URL signatures were redacted (pattern-based, so best effort), and data/MANIFEST.json records each file's source, sha256 and redaction counts. Dataset credits and license texts are in the README.

make experiment   # results/metrics.json
